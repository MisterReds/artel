Мультиагентный харнесс: цель → проект → канбан → команда воркеров с «душой» → менеджер, который не останавливается, пока аудит не подтвердит, что цель достигнута. Скиллы создаются и улучшаются сами. Каждое действие пишется в журнал и видно в дашборде.

Откуда взят каждый механизм:
- [`docs/HARNESS_REGISTRY.md`](docs/HARNESS_REGISTRY.md) — полный реестр (1391 проект из 10 awesome-списков + ручные дополнения, проверены на существование, 877 README разобраны автоматически, ~40 вручную) и таблица «что взято / что следующее».
- [`docs/ANALYSIS.md`](docs/ANALYSIS.md) — разбор исходного кода Hermes Agent, Prime Agent, DeepSeek Harness, OpenClaw и хабов скиллов.

## Установка

Установщик ставит только то, что нужно самому Artel (git, Python 3.10+, GitHub CLI — если нужен вход в GitHub),
при необходимости входит в GitHub по device code (репозиторий приватный), клонирует Artel в `~/.artel/app` (клон —
значит, работает автообновление), создаёт окружение, кладёт команду `artel` в PATH и открывает дашборд. Повторный
запуск обновляет установку на месте.

Codex CLI и Claude Code CLI по умолчанию не ставятся. Когда понадобятся: «Провайдеры» → «Установить» (или
`artel providers install codex|claude`). Ставятся нативные сборки (Codex — из релизов openai/codex, Claude Code —
с downloads.claude.ai с проверкой SHA-256 по манифесту) в `~/.artel/tools/bin`: без прав администратора и без
Node.js. «Удалить» убирает их оттуда.

**Установка одной командой**

Linux / macOS (репозиторий приватный, `gh` уже вошёл в аккаунт):
```bash
gh api repos/MisterReds/artel/contents/install.sh -H "Accept: application/vnd.github.raw" | bash
```
Windows (PowerShell):
```powershell
iex (gh api repos/MisterReds/artel/contents/install.ps1 -H "Accept: application/vnd.github.raw" | Out-String)
```
Если репозиторий публичный:
```bash
curl -fsSL https://raw.githubusercontent.com/MisterReds/artel/master/install.sh | bash
```
```powershell
irm https://raw.githubusercontent.com/MisterReds/artel/master/install.ps1 | iex
```
Опции через pipe: `... | bash -s -- --with-codex --service`. В PowerShell через `iex` опции задаются переменными
окружения: `$env:ARTEL_NOSTART=1; $env:ARTEL_SERVICE=1; $env:ARTEL_WITH_CODEX=1` и т. п. перед командой.
Опции: `--with-codex`, `--with-claude` (сразу поставить CLI), `--service` (дашборд в фоне: systemd --user /
launchd; в Windows — запуск при входе), `--no-start`, `--dir ПУТЬ`, `--yes`.

**Переустановка одной командой**: `artel reinstall` (или `... | bash -s -- --reinstall`,
`$env:ARTEL_REINSTALL=1` перед командой для Windows). Удаляются только свежеклонируемая копия `~/.artel/app` и
окружение `~/.artel/venv` (копия с локальными правками или неотправленными коммитами переезжает в
`~/.artel/app.bak-<время>`), затем всё ставится заново и фоновая служба перезапускается. Конфиг, проекты, ключи и
остальное в `~/.artel` не трогаются. `--yes` — без вопроса.

Вручную (без одной команды): скачайте `install.sh` со страницы репозитория (Raw → сохранить) и выполните
`bash install.sh`; в Windows — `powershell -ExecutionPolicy Bypass -File install.ps1` (опции `-WithCodex`,
`-WithClaude`, `-Service`, `-NoStart`, `-Reinstall`, `-Dir ПУТЬ`).

Подписка Codex: «Провайдеры» → «Установить Codex CLI» → «Войти через device code».

CI (GitHub Actions, `.github/workflows/ci.yml`) на каждый push и pull request проверяет Linux, macOS и Windows:
полный набор тестов, установщик этой системы в чистый домашний каталог, сценарный первый запуск и ответ дашборда.

## Быстрый старт


Без ключа, детерминированно (проверка всей механики): `artel run "любая цель" --provider scripted`.

## Поиск по смыслу (EmbeddingGemma 2, локально)

Агенты находят нужное по смыслу, а не только по словам: планировщик и исполнители получают навыки, подходящие к цели
и роли (закреплённые — всегда), инструмент `search` находит код, документы и результаты по описанию
(«где обрабатываются лимиты провайдера»), запрос и документ могут быть на разных языках.

- **Модель** — Google EmbeddingGemma 2 (Apache-2.0), текстовая часть, GGUF Q8_0 ~310 МБ. Запускается на этом
  компьютере сервером llama.cpp; данные никуда не уходят. Установка: «Провайдеры» → «Эмбеддинги» → «Установить» или
  `artel providers install embeddings` (в `~/.artel/tools`, без прав администратора; контрольная сумма модели
  сверяется с Hugging Face).
- **Без модели ничего не ломается**: поиск идёт по словам (BM25). С моделью результаты BM25 и векторов сливаются.
- **Скорость**: векторы кэшируются (`ARTEL_HOME/embeddings.sqlite`); за один поиск считается ограниченное число новых
  фрагментов, остальное индексируется в фоне. На 4 ядрах CPU ≈ 1 фрагмент кода в секунду при первой индексации.
- **Настройки** (`embeddings` в artel.yaml): `backend: auto | local | http | off`, `dim: 768 | 512 | 256 | 128`
  (Matryoshka), для `http` — `url` любого OpenAI-совместимого `/v1/embeddings` (свой llama-server, Ollama, LM Studio).

## Диагност: почему не работает

Если что-то сломалось, Artel не просто показывает ошибку. Диагност — воркер только для чтения на любой доступной
модели (по возможности не на той, что сломалась) — собирает факты: ошибку, ход задачи и последние сбои проекта,
состояние провайдеров, песочницы Codex, сервера эмбеддингов, переменные прокси — и отвечает: причина, кто
исправляет (Artel, владелец, провайдер), что сделать, строка-доказательство. Без доступной модели отвечают
встроенные правила для известных сбоев (песочница bubblewrap, нет pytest, прокси, лимиты, вход, место на диске).

- Автоматически: когда задача останавливается и ждёт человека, в её обсуждении появляется ответ Диагноста.
- Кнопки «Почему?» — у остановленного проекта, в остановленной задаче, у ошибки эмбеддингов.
- В терминале: `artel why "текст ошибки"`, `artel why --project <slug> [--task <id>]`; `--no-model` — только правила.
- Отчёты хранятся в `ARTEL_HOME/doctor/reports.jsonl`; выключить авторазбор — `doctor: {auto: false}`.

### Отчёты о сбоях

Каждый сбой (разбор Диагноста, необработанная ошибка дашборда, фоновая ошибка менеджера) становится текстовым
отчётом в `ARTEL_HOME/reports/`: что сломалось, причина и шаги, версия Artel и система. До сохранения из него
вырезаются ключи API, токены, e-mail и пути с именем пользователя.

- **Владельцу** — сразу в Telegram, если бот привязан (`reports.telegram`, включено).
- **Разработчикам** — issue в репозитории Artel (метка `artel-report`) через GitHub CLI, которым установщик
  уже вошёл: по кнопке «Отправить разработчикам» (по умолчанию, с показом точного текста) или автоматически
  (`reports.github: auto`). Повтор того же сбоя — комментарий к тому же issue, так видно, как часто он случается.
- Раздел «Сбои» в дашборде; в терминале `artel report list | show <id> | send <id>`.

## Провайдеры и подписки

Раздел «Провайдеры» в дашборде (и `artel providers`) показывает, кто может выполнять работу, и даёт подключить его:

- **Codex — подписка ChatGPT.** Если CLI нет — «Установить» (в `~/.artel/tools`). «Войти через device code» показывает ссылку и одноразовый код; после подтверждения в
  браузере Codex CLI хранит и обновляет вход сам. В терминале: `artel providers login codex`. Рантайм `codex`
  запускает `codex exec --json` в рабочей папке роли; инструменты Artel (сдача задачи, доска, скиллы, вердикты)
  приходят по MCP, все действия Codex пишутся в журнал.
- **Claude Code — подписка Claude.** «Войти через подписку Claude» даёт ссылку; код со страницы входа вставляется в
  дашборд и передаётся CLI (`claude auth login`). «Выйти» — `claude auth logout`. В терминале: `artel providers login|logout claude`.
- **Ключи API** (Anthropic, OpenAI, OpenRouter, DeepSeek…) — только признак «задан / не задан»; значения задаются
  в переменных окружения и нигде не показываются.
- **Роли → рантайм.** Для каждой роли можно выбрать Artel / Claude Code / Codex и модель; сохраняется в
  `ARTEL_HOME/artel.yaml`. Разные подписки на разных ролях разносят нагрузку по их лимитам.
- **Модели — из списка.** Модели Codex берутся у самого CLI (`codex debug models`) и выбираются из списка; имя
  в любом регистре или отображаемое имя («GPT-6-Luna») приводится к id, неизвестное отклоняется с перечнем
  доступных. Claude Code списка моделей не отдаёт: алиасы (fable, opus, sonnet…) берутся из справки установленного CLI, любое полное имя — через «другая модель…».
- **Лимит → переключение.** Когда подписка упирается в лимит, отметка до времени сброса пишется в
  `ARTEL_HOME/limits.json`, и задача (и планирование) сразу уходит на следующий подключённый исполнитель — в том
  числе если рантайм выбран явно (`failover: false` в artel.yaml оставляет ждать сброса). Отметку можно снять.
- **Отключение.** Флажок «использовать в работе» на карточке (`disabled_runtimes`) исключает исполнителя из выбора.
- **Одобрения.** Codex работает автономно: `approval_policy=never` значит «не спрашивать» (спрашивать некого);
  команды ограничены песочницей `workspace-write` и политикой команд Artel, инструменты Artel одобрены заранее.
- **CLI.** `artel providers` — состояние; `artel providers use codex [--role planner]`, `models codex`,
  `model codex gpt-6-luna`, `disable claude`, `enable claude`, `unlimit claude`.
- **Часовой пояс.** Настройка `ui.timezone` (имя IANA, например `Asia/Sakhalin`; пусто — системный пояс) задаётся
  на странице «Провайдеры» и хранится в `ARTEL_HOME/artel.yaml`. В этом поясе показывается любое время: в дашборде,
  выводе CLI и уведомлениях; неверное имя отклоняется.

## Telegram: Artel с телефона

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и задайте его токен в переменной окружения
   `ARTEL_TELEGRAM_TOKEN` (не в чате и не в файлах).
2. Запустите `artel web` (бот стартует вместе с дашбордом) или только бота: `artel telegram`.
3. Привяжите свой чат: отправьте боту `/pair КОД`. Код одноразовый, действует 15 минут, показывается в терминале и
   в дашборде (Провайдеры → Telegram); новый — `artel telegram pair`. Непривязанным чатам бот ничего не показывает.

Что умеет: прислать текст — начать цель (с подтверждением); `/status`, `/projects`, `/p N` — что происходит;
`/answer N текст` — ответить проекту, который ждёт вас; `/stop N`, `/resume N`; `/update` — обновить Artel.
Сам пишет, когда цель достигнута, когда нужен человек (с причиной), при ошибке, при исчерпании бюджета и когда
вышло обновление.

## Доступ с телефона

Дашборд можно открыть с телефона и установить как приложение (PWA: «На экран Домой» в Safari, «Установить
приложение» в Chrome).

1. `artel web --remote` (или в `~/.artel/artel.yaml`: `web: {remote: true}`) — дашборд слушает не только localhost,
   но пускает только после входа. Токен доступа печатается в терминале один раз; хранится только его хэш
   (`~/.artel/web_auth.json`). Новый токен — `artel web token --new`, все прежние входы при этом закрываются.
2. На телефоне откройте адрес и введите токен — вход запоминается на 30 дней (cookie HttpOnly, SameSite=Strict).
   Пять неверных попыток с одного адреса — пауза 10 минут.
3. **Только через HTTPS**: без него токен и сессия идут по сети открытым текстом (дашборд покажет предупреждение).
   Рецепты с Caddy (свой домен) и Tailscale (без домена, приватно) — в [docs/REMOTE.md](docs/REMOTE.md).

Без `--remote` всё как раньше: только 127.0.0.1, без входа.

## Обновление

Artel ставится клоном репозитория (`git clone … && pip install -e .`) и обновляется сам: в дашборде кнопка
«Обновление (N)» появляется, когда в канале (`origin/master` — туда эволюция вливает только проверенное) есть новые
изменения. Окно показывает новые пункты дорожной карты и список изменений. «Обновить» сначала прогоняет тесты опор
на новой версии во временной копии (при провале ничего не меняется), затем перематывает установку вперёд,
переустанавливает зависимости, если они поменялись, и перезапускает дашборд, когда идущие проекты закончатся.
«Откатить последнее» возвращает предыдущую версию.

```bash
artel update --check      # что нового
artel update              # проверить и установить
artel update --rollback   # вернуть предыдущую версию
```

Настройки: `update: {remote: origin, branch: master, verify: invariants|full|none, check_interval_min: 30}`.
Локальные правки в коде установки блокируют обновление (оно только перематывает вперёд и ничего не перезаписывает).

## Как это работает

```
цель ──► Architect ──► submit_plan: ростер воркеров + DAG задач с критериями и гейтами
                         │
             ┌───────────▼────────────── Manager (цикл до результата) ───────────────┐
             │ todo ─► ready ─► running ─► review ─► done                            │
             │                   │  worker: агентный цикл, свой workspace, SOUL/RULES/MEMORY
             │                   │  конец хода без task_submit → continuation-промпт  │
             │                   │  3 хода без действий → stalled → backoff 10s·2ⁿ    │
             │                   └► review: shell-гейты + независимый ревьюер         │
             │ отказ / N неудач → blocked → replan: retry | reassign | split | cancel | escalate
             │ всё done → аудит цели → не достигнута? → новые задачи → снова в работу │
             └───────────────────────────────────────────────────────────────────────┘
после принятой задачи (≥5 tool calls) → Librarian: создать/исправить скилл (ledger, откат)
серия неудач и финал → Refiner: правки prompt_notes / RULES.md со снапшотами
```

| Модуль | Назначение |
|---|---|
| `artel/kernel.py` | Микроядро: сервисы, хуки, waterfall (`tool/execute`, `llm/request`), реестр тулов, `events.jsonl` |
| `artel/board.py` | Канбан на SQLite: DAG, CAS-claim, попытки (`runs`), комментарии-blackboard |
| `artel/project.py` | Проект, конфиг, персоны воркеров (`SOUL.md`, `IDENTITY.md`, `RULES.md`, `MEMORY.md`, `workspace/`) |
| `artel/agent.py` | Общий агентный цикл: терминальные тулы, continuation, no-progress cap, бюджеты, лог каждого запроса |
| `artel/manager.py` | Планирование, диспетчеризация, ревью, перепланирование, аудит, обучение, refine, восстановление после рестарта |
| `artel/skills.py` | Библиотека в формате Agent Skills: валидация, guard по уровням доверия, ledger + rollback, lifecycle, импорт из хабов |
| `artel/refine.py` | Continual Harness: малые правки с доказательствами, журнал, откат |
| `artel/plugins/*` | Провайдеры (Anthropic SDK, OpenAI-compatible, scripted), тулы (shell/файлы/память, скиллы, доска) |
| `artel/web/` | Дашборд: проекты, команда, доска, живая лента событий (SSE), файлы результата, сообщения исполнителю |

### Гарантии завершения

- Задача закрывается только через `task_submit` с доказательствами; правка кода без запуска — отказ.
- `done` ставит ревьюер после прохождения гейтов, не воркер.
- Корневая цель закрывается только аудитом; неполнота превращается в новые задачи.
- Остановка возможна только по: аудиту, бюджету (`budgets.max_total_tokens`, `max_hours`), команде человека, или когда все оставшиеся пути ждут человека (`escalate`). `artel comment <проект> <задача> "..."` снимает такой блок, `artel resume` продолжает.

### Скиллы

```bash
artel skills import anthropics/skills          # trusted: guard блокирует только dangerous
artel skills import openai/skills
artel skills import some/repo                  # community: блокирует caution и dangerous
artel skills list | view <name> | ledger [<name>] | rollback <entry> | pin <name> | curate
```
Агенты правят только свои (`origin: agent`), незакреплённые скиллы; правка требует свежего `skill_view` (read-before-write). Неиспользуемые скиллы: `active → stale (30 дн) → archived (90 дн)`, удаления нет.

### Расширение (плагины)

```python
# mypkg/approval.py ; в artel.yaml: plugins: [mypkg.approval]
def setup(kernel):
    def gate(ctx, next_):
        if ctx["name"] == "bash" and "rm -rf" in ctx["args"]["command"]:
            return "denied by policy", True
        return next_()
    kernel.on("tool/execute", gate, priority=10)
```

## Плагины

Плагин — модуль с `setup(kernel)` и манифестом `PLUGIN = {name, version, provides, requires, permissions}`. Плагины
собираются в пакеты и ставятся из git, из pip (PyPI) или из папки:

```bash
artel plugins install https://github.com/owner/artel-plugin-x     # git (можно @тег или @коммит)
artel plugins install artel-plugin-x==1.2                         # pip / PyPI
artel plugins install ./examples/artel-plugin-hello               # локальная папка
artel plugins list                       # встроенные и установленные: состояние, версия, разрешения, ошибка
artel plugins show artel-plugin-hello    # манифест: provides, requires, какие разрешения просит
artel plugins enable artel-plugin-hello  # показывает манифест, спрашивает подтверждение (--yes без вопроса)
artel plugins disable|update|remove artel-plugin-hello            # update all — обновить все пакеты
```

- Пакет ставится в свою папку `ARTEL_HOME/plugins/<имя>` (`pip install --target`, зависимости там же) и
  записывается в `ARTEL_HOME/plugins.json`: источник, версия, коммит, точки входа, манифест, флаг включения, ошибка.
- **Установка не запускает код пакета** — работает только pip и сборщик пакета. Манифест читается статически
  (`ast`, без импорта). Пакет ставится выключенным; его `setup` выполняется только после включения.
- Включение пробно загружает плагин; если импорт или `setup` падает, эффекты откатываются, пакет остаётся
  выключенным, ошибка видна в `list` и в дашборде. Сломанный плагин никогда не роняет Artel.
- Если новая версия просит новые разрешения, `update` выключает пакет до повторного подтверждения.
- Плагин работает внутри процесса Artel с его правами: разрешения — это декларация для человека, а не песочница.
  Ставьте только то, чему доверяете.

Пакет объявляет плагины точкой входа (пример — `examples/artel-plugin-hello`):

```toml
[project.entry-points."artel.plugins"]
hello = "artel_plugin_hello"
```

Папка без сборки может вместо этого содержать `artel-plugin.toml` (`name`, `version`, `[plugins] имя = "модуль"`).

**События жизненного цикла** (`kernel.on(событие, fn)`, обработчик получает именованные аргументы; ошибка
обработчика пишется в журнал как `plugin/error` и не ломает работу):

| Событие | Когда | Данные |
|---|---|---|
| `project_start` | менеджер начал вести проект | `project`, `resumed` |
| `before_agent_start` | перед запуском любой роли | `project`, `role`, `purpose`, `task`, `persona`, `agent` — изменяемый: `system`, `first_user`, `tool_names` |
| `agent_end` | роль закончила запуск | `project`, `role`, `purpose`, `task`, `outcome` |
| `task_done` | ревьюер принял задачу | `project`, `task`, `feedback` |
| `project_end` | проект остановился (любой итог) | `project`, `status`, `usage` |
| `session_shutdown` | ядро завершает работу (конец `run`/`resume`, остановка `web`) | `reason` |

```python
def setup(kernel):
    def before(*, agent, **_):
        agent["system"] += "\n\nОтвечай коротко."
    kernel.on("before_agent_start", before)
```

В дашборде раздел **«Плагины»**: встроенные и установленные плагины, состояние, манифест и разрешения, включение
с подтверждением, выключение, обновление, удаление, установка по ссылке. Изменения применяются к работающему
серверу сразу.

## Рантайм Claude Code

`runtime: claude_code` в `~/.artel/artel.yaml` (или `artel run … --runtime claude_code`) — каждую роль исполняет
Claude Code CLI в headless-режиме (`claude -p`, stream-json) с моделью из `claude_code.model` (по умолчанию `sonnet`).
Claude Code работает своими инструментами (Bash, Edit, Read, Grep), а инструменты Artel (`task_submit`, доска,
скиллы, память, вердикты) получает через MCP-прокси, который пересылает вызовы в процесс Artel. Каждый шаг Claude Code
попадает в ленту событий; фактическая стоимость (`total_cost_usd`) учитывается по проекту и запуску. Роли
планирования и проверки (planner, reviewer, auditor, manager, evolver, absorber) не могут редактировать файлы.

```yaml
runtime: claude_code
claude_code: {model: sonnet, max_resumes: 2, timeout_s: 1800}
runtime_by_role: {reviewer: native}   # смешивать рантаймы по ролям
```

## Изоляция и песочница

Обе функции включаются явно; по умолчанию поведение прежнее.

```yaml
isolation: {worktrees: true}          # своя git-копия результатов на каждую задачу
sandbox:
  mode: auto                          # off (по умолчанию) | auto | bwrap | seatbelt
  network: true                       # false — команды без сети
  writable: []                        # дополнительные пути для записи
  temp: true                          # можно писать во временный каталог
  require: false                      # true — без песочницы команда не запускается
  gates: false                        # true — проверки ревью (checks) тоже в песочнице
```

**Изоляция задач (git worktree).** Каждая задача получает свой worktree общих результатов
(`<проект>/worktrees/<id>`, ветка `task/<id>` в отдельном репозитории `<проект>/isolation.git`; `.git` самого
каталога результатов не трогается). Для исполнителя `shared/...`, `$ARTEL_SHARED` и `--add-dir` у Claude Code / Codex
указывают на этот worktree, поэтому параллельные задачи не видят и не портят чужую незаконченную работу. Перед ревью
в worktree вливается текущее состояние `shared/`: ревьюер и проверки видят работу такой, какой она ляжет. После
принятия ревьюером изменения сливаются в общий `shared/`, worktree удаляется. Отказ «начни заново» сбрасывает
worktree к текущему `shared/`; отменённая задача удаляет свой worktree. Если две задачи изменили одни и те же строки,
ничего не перезаписывается: задача получает комментарий `MERGE CONFLICT` со списком файлов, в её worktree лежит
обновлённая база с маркерами конфликта, и исполнитель разрешает их в следующей попытке (попытка засчитывается в лимит
`max_attempts`). Правки людей в `shared/` становятся базой для всех следующих слияний. Файлы из `.gitignore`
(например, `node_modules`) в worktree не попадают.

**Песочница для команд.** Команды инструмента `bash` (и проверки ревью при `gates: true`) запускаются в песочнице ОС:
на Linux — bubblewrap (`apt-get install bubblewrap`), на macOS — `sandbox-exec`. Вся система видна только для
чтения; писать можно только в worktree задачи (или `shared/` без изоляции), в свой workspace, во временный каталог и
в `writable`. Сеть по умолчанию разрешена. Если песочница недоступна (нет bwrap, контейнер без user namespaces,
Windows), команда выполняется без неё, а в результате и в журнале (`sandbox/unavailable`) есть явная пометка;
`require: true` вместо этого отказывает. Правила политики команд (`policy`) действуют как прежде. Рантаймы Claude
Code и Codex запускают команды своими инструментами и своей песочницей (у Codex — `workspace-write` с worktree задачи).

**Проверки задач и политика.** Проверки (`checks`) проходят через ту же политику команд. Спросить разрешение им не у кого,
поэтому вердикт `prompt` для проверки равен отказу: «blocked by policy (prompt): …; task checks cannot ask for approval —
change the check or the policy». Переключатель в конфиге: `gates: {policy: enforce}` (по умолчанию) или `off`.

## Самоулучшение: Artel улучшает Artel

**Дорожная карта** — `roadmap.yaml` (пункты, откуда взяты, что внедряется) и `harnesses.yaml` (главные харнессы:
индекс значимости, их ключевые механизмы и есть ли они в Artel). Страница с рейтингом, покрытием и планом —
[`docs/roadmap.html`](docs/roadmap.html) (`artel roadmap html`); таблица — [`docs/ROADMAP.md`](docs/ROADMAP.md)
(`artel roadmap render`). Значимость: популярность, сообщество, признание кураторов, живость и «первоисточник»
(экспертная оценка с обоснованием); пункты с приоритетом «ядро» — механизмы лидеров, которых в Artel нет, — идут
первыми, а `artel roadmap study` предлагает изучать сначала главные харнессы.

```bash
artel bench                         # набор задач со скрытыми проверками → pass, partial, $, время, отказы, срывы
artel doctor --bench suite.json     # здоровье кода + профиль траекторий: где срывы, за что отказы, куда уходят деньги
artel evolve --generations 3 --candidates 2
artel absorb owner/repo --focus "verification" --run   # разобрать чужой харнесс и перенести лучшие функции
artel evolution                     # журнал экспериментов
```

Поколение эволюции:
1. **Базовый замер** чемпиона (`master`) на бенчмарке; результат кэшируется по коммиту.
2. **Диагностика**: проваленные скрытые проверки, срывы, отказы ревью, ошибки инструментов, доля затрат по ролям.
3. **Гипотезы**: агент-эволюционер читает диагностику, карту кода и журнал прошлых экспериментов (что помогло, что
   навредило и почему) и предлагает K изменений с ожидаемым эффектом на метрику.
4. **Реализация**: на каждую гипотезу — ветка `evolve/gN-k-…` и worktree; **реализует её сам Artel** (проект с
   `--workdir` = worktree). Для абсорбции команда получает исходники чужого харнесса как read-only источник
   (с учётом лицензии: MIT/Apache/BSD — перенос с атрибуцией, иначе — переписать идею).
5. **Проверка**: собственный набор тестов кандидата должен пройти.
6. **Замер**: бенчмарк кодом кандидата; сравнение по каждой метрике и каждой задаче.
7. **Отбор**: лучший кандидат, превзошедший чемпиона без регрессий, вливается (`--no-ff`) и тегается
   `evolve-gen-N`; остальные ветки остаются в git, вердикт и дельты — в журнале.

### Популяция из десятков гипотез

```bash
artel evolve --candidates 20 --parallel-candidates 4 --screen-tasks adr-doc,csv-report --finalists 4 --budget 80
```

1. Все кандидаты реализуются параллельно (каждый в своём worktree) и проходят свои тесты.
2. **Отсев**: выжившие прогоняются на дешёвом подмножестве задач; регресс на любой задаче — выбывание.
3. **Финалисты**: лучшие `--finalists` по оценке отсева получают полный бенчмарк.
4. **Стопка**: все принятые кандидаты по очереди вливаются в `evolve/gN-stack`; после каждого слияния —
   тесты; конфликт или падение исключают кандидата. Стопка проходит полный бенчмарк и вливается, если не хуже
   лучшего одиночки; иначе вливается лучший одиночка.
5. `--budget` останавливает новые реализации и замеры, когда деньги поколения кончились.

### Эволюция на двух подписках

```yaml
# ~/.artel/artel.yaml
evolve:
  runtimes: [claude_code, codex]   # порядок предпочтения
```

или `artel evolve --roadmap 2 --runtimes claude_code,codex`. Когда у Claude Code кончается лимит, реализация и
бенчмарк продолжаются на Codex (и наоборот); незаконченная реализация доделывается в том же worktree. Рантайм с
лимитом снова используется после сброса. Пауза — только если лимит у обеих подписок; `artel evolve` ждёт самого
раннего сброса и продолжает сам. Сравнения честные: базовый замер чемпиона снимается и кэшируется отдельно для
каждого рантайма, кандидат сравнивается только с замером на своём. `artel evolution` показывает рантайм каждого
замера и текущие лимиты.

Скрытые проверки бенчмарка копируются в рабочий каталог только после завершения проекта: агенты их не видят и не
могут под них подгонять. Задачи — `evals/tasks/<id>/{task.yaml,seed/,hidden/}`.

В дашборде раздел **«Эволюция»**: прогресс чемпиона по коммитам, поколения, кандидаты с решением и причиной, дельты
метрик (что улучшило, что ухудшило), разбивка по задачам, отчёты абсорбции, последняя диагностика.

### Эволюция переживает свой процесс

Поколение не теряется, если его процесс умер (перезагрузка, убитый контейнер, нехватка памяти). Работающий
`artel evolve` раз в 30 с обновляет `heartbeat.json`; дашборд (`artel web`) каждые 2 минуты находит поколения,
отмеченные как идущие, у которых процесса больше нет, и продолжает их той же командой с `--resume`. Без дашборда то
же делает `artel evolve --supervise`. Если продолженный процесс трижды подряд падает в первые 5 минут, перезапуски
прекращаются и причина показывается на странице «Эволюция». Отключить: `evolve.auto_resume: false`.

Над одним репозиторием одновременно идёт только одна эволюция (блокировка в `.git/artel-evolve.lock`): второй
`artel evolve` — из другого ARTEL_HOME или после восстановления журнала — не запустится, пока работает первый.
