Мультиагентный харнесс: цель → проект → канбан → команда ботов с «душой» → менеджер, который не останавливается, пока аудит не подтвердит, что цель достигнута. Скиллы создаются и улучшаются сами. Каждое действие пишется в журнал и видно в дашборде.

Откуда взят каждый механизм:
- [`docs/HARNESS_REGISTRY.md`](docs/HARNESS_REGISTRY.md) — полный реестр (1391 проект из 10 awesome-списков + ручные дополнения, проверены на существование, 877 README разобраны автоматически, ~40 вручную) и таблица «что взято / что следующее».
- [`docs/ANALYSIS.md`](docs/ANALYSIS.md) — разбор исходного кода Hermes Agent, Prime Agent, DeepSeek Harness, OpenClaw и хабов скиллов.

## Установка

Установщик ставит только то, что нужно самому Artel (git, Python 3.10+, GitHub CLI — если нужен вход в GitHub),
при необходимости входит в GitHub по device code (репозиторий приватный), клонирует Artel в `~/.artel/app` (клон —
значит, работает автообновление), создаёт окружение, кладёт команду `artel` в PATH и открывает дашборд. Повторный
запуск обновляет установку на месте.

Codex CLI и Claude Code CLI по умолчанию не ставятся. Когда понадобятся: «Провайдеры» → «Установить» (или
`artel providers install codex|claude`). Ставятся нативные сборки (Codex — из релизов openai/codex, Claude Code —
с downloads.claude.ai с проверкой SHA-256 по манифесту) в `~/.artel/tools/bin`: без прав администратора и без
Node.js. «Удалить» убирает их оттуда.

**Linux / macOS**
```bash
# если GitHub CLI уже вошёл в аккаунт:
bash <(gh api repos/MisterReds/artel/contents/install.sh -H "Accept: application/vnd.github.raw")
# иначе: скачайте install.sh со страницы репозитория (Raw → сохранить) и выполните
bash install.sh
```
Опции: `--with-codex`, `--with-claude` (сразу поставить CLI), `--service` (дашборд в фоне: systemd --user /
launchd), `--no-start`, `--dir ПУТЬ`.

**Windows** (PowerShell): скачайте `install.ps1` и выполните
```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```
Опции: `-WithCodex`, `-WithClaude`, `-Service` (запуск дашборда при входе в Windows), `-NoStart`, `-Dir ПУТЬ`.

Подписка Codex: «Провайдеры» → «Установить Codex CLI» → «Войти через device code».

CI (GitHub Actions, `.github/workflows/ci.yml`) на каждый push и pull request проверяет Linux, macOS и Windows:
полный набор тестов, установщик этой системы в чистый домашний каталог, сценарный первый запуск и ответ дашборда.

## Быстрый старт

```bash
pip install -e .
export ANTHROPIC_API_KEY=...            # или `ant auth login`
artel run "Сделай CLI-утилиту на Python: CSV → JSON, с тестами и README" --web
# дашборд: http://127.0.0.1:8765
```

Без ключа, детерминированно (проверка всей механики): `artel run "любая цель" --provider scripted`.

DeepSeek / OpenRouter / Ollama: в `~/.artel/artel.yaml`
```yaml
provider: openai_compat
openai_compat: {base_url: https://api.deepseek.com/v1, api_key_env: DEEPSEEK_API_KEY}
models: {default: deepseek-chat}
```

## Провайдеры и подписки

Раздел «Провайдеры» в дашборде (и `artel providers`) показывает, кто может выполнять работу, и даёт подключить его:

- **Codex — подписка ChatGPT.** Если CLI нет — «Установить» (в `~/.artel/tools`). «Войти через device code» показывает ссылку и одноразовый код; после подтверждения в
  браузере Codex CLI хранит и обновляет вход сам. В терминале: `artel providers login codex`. Рантайм `codex`
  запускает `codex exec --json` в рабочей папке роли; инструменты Artel (сдача задачи, доска, скиллы, вердикты)
  приходят по MCP, все действия Codex пишутся в журнал.
- **Claude Code — подписка Claude.** Статус входа установленного CLI; вход — `claude`, затем `/login`.
- **Ключи API** (Anthropic, OpenAI, OpenRouter, DeepSeek…) — только признак «задан / не задан»; значения задаются
  в переменных окружения и нигде не показываются.
- **Роли → рантайм.** Для каждой роли можно выбрать Artel / Claude Code / Codex и модель; сохраняется в
  `ARTEL_HOME/artel.yaml`. Разные подписки на разных ролях разносят нагрузку по их лимитам.
- **Часовой пояс.** Настройка `ui.timezone` (имя IANA, например `Asia/Sakhalin`; пусто — системный пояс) задаётся
  на странице «Провайдеры» и хранится в `ARTEL_HOME/artel.yaml`. В этом поясе показывается любое время: в дашборде,
  выводе CLI и уведомлениях; неверное имя отклоняется.

## Обновление

Artel ставится клоном репозитория (`git clone … && pip install -e .`) и обновляется сам: в дашборде кнопка
«Обновление (N)» появляется, когда в канале (`origin/master` — туда эволюция вливает только проверенное) есть новые
изменения. Окно показывает новые пункты дорожной карты и список изменений. «Обновить» сначала прогоняет тесты опор
на новой версии во временной копии (при провале ничего не меняется), затем перематывает установку вперёд,
переустанавливает зависимости, если они поменялись, и перезапускает дашборд, когда идущие проекты закончатся.
«Откатить последнее» возвращает предыдущую версию.

```bash
artel update --check      # что нового
artel update              # проверить и установить
artel update --rollback   # вернуть предыдущую версию
```

Настройки: `update: {remote: origin, branch: master, verify: invariants|full|none, check_interval_min: 30}`.
Локальные правки в коде установки блокируют обновление (оно только перематывает вперёд и ничего не перезаписывает).

## Как это работает

```
цель ──► Architect ──► submit_plan: ростер ботов + DAG задач с критериями и гейтами
                         │
             ┌───────────▼────────────── Manager (цикл до результата) ───────────────┐
             │ todo ─► ready ─► running ─► review ─► done                            │
             │                   │  worker: агентный цикл, свой workspace, SOUL/RULES/MEMORY
             │                   │  конец хода без task_submit → continuation-промпт  │
             │                   │  3 хода без действий → stalled → backoff 10s·2ⁿ    │
             │                   └► review: shell-гейты + независимый ревьюер         │
             │ отказ / N неудач → blocked → replan: retry | reassign | split | cancel | escalate
             │ всё done → аудит цели → не достигнута? → новые задачи → снова в работу │
             └───────────────────────────────────────────────────────────────────────┘
после принятой задачи (≥5 tool calls) → Librarian: создать/исправить скилл (ledger, откат)
серия неудач и финал → Refiner: правки prompt_notes / RULES.md со снапшотами
```

| Модуль | Назначение |
|---|---|
| `artel/kernel.py` | Микроядро: сервисы, хуки, waterfall (`tool/execute`, `llm/request`), реестр тулов, `events.jsonl` |
| `artel/board.py` | Канбан на SQLite: DAG, CAS-claim, попытки (`runs`), комментарии-blackboard |
| `artel/project.py` | Проект, конфиг, персоны воркеров (`SOUL.md`, `IDENTITY.md`, `RULES.md`, `MEMORY.md`, `workspace/`) |
| `artel/agent.py` | Общий агентный цикл: терминальные тулы, continuation, no-progress cap, бюджеты, лог каждого запроса |
| `artel/manager.py` | Планирование, диспетчеризация, ревью, перепланирование, аудит, обучение, refine, восстановление после рестарта |
| `artel/skills.py` | Библиотека в формате Agent Skills: валидация, guard по уровням доверия, ledger + rollback, lifecycle, импорт из хабов |
| `artel/refine.py` | Continual Harness: малые правки с доказательствами, журнал, откат |
| `artel/plugins/*` | Провайдеры (Anthropic SDK, OpenAI-compatible, scripted), тулы (shell/файлы/память, скиллы, доска) |
| `artel/web/` | Дашборд: проекты, команда, доска, живая лента событий (SSE), файлы результата, сообщения исполнителю |

### Гарантии завершения

- Задача закрывается только через `task_submit` с доказательствами; правка кода без запуска — отказ.
- `done` ставит ревьюер после прохождения гейтов, не воркер.
- Корневая цель закрывается только аудитом; неполнота превращается в новые задачи.
- Остановка возможна только по: аудиту, бюджету (`budgets.max_total_tokens`, `max_hours`), команде человека, или когда все оставшиеся пути ждут человека (`escalate`). `artel comment <проект> <задача> "..."` снимает такой блок, `artel resume` продолжает.

### Скиллы

```bash
artel skills import anthropics/skills          # trusted: guard блокирует только dangerous
artel skills import openai/skills
artel skills import some/repo                  # community: блокирует caution и dangerous
artel skills list | view <name> | ledger [<name>] | rollback <entry> | pin <name> | curate
```
Агенты правят только свои (`origin: agent`), незакреплённые скиллы; правка требует свежего `skill_view` (read-before-write). Неиспользуемые скиллы: `active → stale (30 дн) → archived (90 дн)`, удаления нет.

### Расширение (плагины)

```python
# mypkg/approval.py ; в artel.yaml: plugins: [mypkg.approval]
def setup(kernel):
    def gate(ctx, next_):
        if ctx["name"] == "bash" and "rm -rf" in ctx["args"]["command"]:
            return "denied by policy", True
        return next_()
    kernel.on("tool/execute", gate, priority=10)
```

## Дашборд: много проектов одновременно

`artel web` → http://127.0.0.1:8765. Сервер ведёт любое число проектов параллельно; у каждого своя ссылка `#/p/<slug>`.

- **Портфель** — все проекты: этап (планирование → исполнение → ревью → аудит → готово), сегментный прогресс по статусам задач, кто из ботов чем занят, последнее событие, стоимость, бюджетные алерты; сводка «требует внимания» по всем проектам.
- **Проект** — шкала этапов, команда со статистикой, канбан, живая лента событий, путь каждой задачи по этапам с временем и исполнителем, доказательства, запуски, сообщение исполнителю, файлы результата.
- **Агенты** — как справляются модели, роли и конкретные боты во всех проектах: принято, с первой попытки, отказы ревью, доля срывов, токены и $ на принятую задачу.
- **Реестр харнессов** — 1391 проект с фильтрами по типу, признакам и поиском.
- **Скиллы** — общая библиотека и история правок каждого скилла.

## Рантайм Claude Code

`runtime: claude_code` в `~/.artel/artel.yaml` (или `artel run … --runtime claude_code`) — каждую роль исполняет
Claude Code CLI в headless-режиме (`claude -p`, stream-json) с моделью из `claude_code.model` (по умолчанию `sonnet`).
Claude Code работает своими инструментами (Bash, Edit, Read, Grep), а инструменты Artel (`task_submit`, доска,
скиллы, память, вердикты) получает через MCP-прокси, который пересылает вызовы в процесс Artel. Каждый шаг Claude Code
попадает в ленту событий; фактическая стоимость (`total_cost_usd`) учитывается по проекту и запуску. Роли
планирования и проверки (planner, reviewer, auditor, manager, evolver, absorber) не могут редактировать файлы.

```yaml
runtime: claude_code
claude_code: {model: sonnet, max_resumes: 2, timeout_s: 1800}
runtime_by_role: {reviewer: native}   # смешивать рантаймы по ролям
```

## Самоулучшение: Artel улучшает Artel

```bash
artel bench                         # набор задач со скрытыми проверками → pass, partial, $, время, отказы, срывы
artel doctor --bench suite.json     # здоровье кода + профиль траекторий: где срывы, за что отказы, куда уходят деньги
artel evolve --generations 3 --candidates 2
artel absorb owner/repo --focus "verification" --run   # разобрать чужой харнесс и перенести лучшие функции
artel evolution                     # журнал экспериментов
```

Поколение эволюции:
1. **Базовый замер** чемпиона (`master`) на бенчмарке; результат кэшируется по коммиту.
2. **Диагностика**: проваленные скрытые проверки, срывы, отказы ревью, ошибки инструментов, доля затрат по ролям.
3. **Гипотезы**: агент-эволюционер читает диагностику, карту кода и журнал прошлых экспериментов (что помогло, что
   навредило и почему) и предлагает K изменений с ожидаемым эффектом на метрику.
4. **Реализация**: на каждую гипотезу — ветка `evolve/gN-k-…` и worktree; **реализует её сам Artel** (проект с
   `--workdir` = worktree). Для абсорбции команда получает исходники чужого харнесса как read-only источник
   (с учётом лицензии: MIT/Apache/BSD — перенос с атрибуцией, иначе — переписать идею).
5. **Проверка**: собственный набор тестов кандидата должен пройти.
6. **Замер**: бенчмарк кодом кандидата; сравнение по каждой метрике и каждой задаче.
7. **Отбор**: лучший кандидат, превзошедший чемпиона без регрессий, вливается (`--no-ff`) и тегается
   `evolve-gen-N`; остальные ветки остаются в git, вердикт и дельты — в журнале.

### Популяция из десятков гипотез

```bash
artel evolve --candidates 20 --parallel-candidates 4 --screen-tasks adr-doc,csv-report --finalists 4 --budget 80
```

1. Все кандидаты реализуются параллельно (каждый в своём worktree) и проходят свои тесты.
2. **Отсев**: выжившие прогоняются на дешёвом подмножестве задач; регресс на любой задаче — выбывание.
3. **Финалисты**: лучшие `--finalists` по оценке отсева получают полный бенчмарк.
4. **Стопка**: все принятые кандидаты по очереди вливаются в `evolve/gN-stack`; после каждого слияния —
   тесты; конфликт или падение исключают кандидата. Стопка проходит полный бенчмарк и вливается, если не хуже
   лучшего одиночки; иначе вливается лучший одиночка.
5. `--budget` останавливает новые реализации и замеры, когда деньги поколения кончились.

Скрытые проверки бенчмарка копируются в рабочий каталог только после завершения проекта: агенты их не видят и не
могут под них подгонять. Задачи — `evals/tasks/<id>/{task.yaml,seed/,hidden/}`.

В дашборде раздел **«Эволюция»**: прогресс чемпиона по коммитам, поколения, кандидаты с решением и причиной, дельты
метрик (что улучшило, что ухудшило), разбивка по задачам, отчёты абсорбции, последняя диагностика.

## Состояние и дальнейшие шаги

Работает и покрыто тестами на scripted-провайдере. Запрос к Claude проверен на фейковом эндпоинте (формат, beta-заголовок fallbacks, сохранение thinking-блоков). Прогон с реальной моделью не выполнялся — в окружении разработки нет ключа.

Следующее: изоляция воркеров (git worktree / контейнер на воркера), компакция длинных прогонов, бенчмарк-раннер (SWE-bench / ARC-AGI-3), семантический поиск скиллов, mailbox между воркерами, параллельные варианты решения с выбором лучшего (best-of-N).
