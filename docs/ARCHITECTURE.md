# Архитектура Artel: опорные механизмы

Опорный механизм — это часть, ради которой Artel существует. Его контракт закреплён тестами в
`tests/test_invariants.py`. Кандидат эволюции, который ломает контракт, не проходит тесты и не вливается,
каким бы хорошим ни был его бенчмарк. Менять опорный механизм можно только осознанным решением,
записанным в этот файл, — не побочным эффектом.

| Опора | Источник | Контракт (что нельзя потерять) | Где | Инварианты |
|---|---|---|---|---|
| **Модульность** | DeepSeek Harness (Cordis) | Каждая способность — плагин с манифестом; регистрации — обратимые эффекты; выгрузка восстанавливает перекрытое; сбой `setup` откатывается; рантаймы, провайдеры, инструменты заменяемы конфигом; горячий путь — поиск в словаре | `kernel.py`, `plugins/` | `test_modularity_*` |
| **Скиллы** | Hermes Agent | Формат Agent Skills; библиотекарь после трудных задач; read-before-write; агент правит только своё; журнал правок и откат; lifecycle без удаления; guard по доверию | `skills.py`, `plugins/skill_tools.py`, `manager.py` | `test_skills_*` |
| **Цикл до результата** | Prime Agent | Ход без терминального инструмента → продолжение; холостые ходы → stalled → backoff; сдача только с доказательствами; `done` ставит ревьюер, цель закрывает аудитор; ошибка настройки (нет CLI, нет входа) сразу идёт человеку, лимит провайдера ждёт сброса, а сбой, который не лечат ни повторы, ни `max_replans` перепланирований, передаётся человеку — бесконечного круга нет | `agent.py`, `plugins/board_tools.py`, `manager.py` | `test_loop_*`, `test_setup_errors_*` |
| **Боты с душой** | OpenClaw | У исполнителя SOUL / IDENTITY / RULES / MEMORY и свой workspace; SOUL в системном промпте | `project.py`, `manager.py` | `test_workers_have_souls_and_workspaces` |
| **Прозрачность** | DeepSeek Harness | Append-only журнал; каждый вызов модели и инструмента записан; `tool/call` ↔ `tool/result`; монотонный `seq` | `kernel.py` (`EventLog`) | `test_event_log_is_complete_and_ordered` |
| **Канбан** | Hermes Agent | DAG без циклов; CAS-захват — ровно один исполнитель | `board.py` | `test_board_cas_claim_and_cycles` |
| **Измеряемая эволюция** | auto-harness, Gear, Ouroboros | Кандидат вливается только после тестов (включая инварианты) и бенчмарка со скрытыми проверками | `evolve/` | `test_failing_tests_reject_candidate`, `test_population_*` |

## Как устроена модульность

```
build_kernel(config)
  └─ load_plugin(dotted)            манифест PLUGIN = {name, version, provides, requires}
       ├─ requires проверяются до setup
       ├─ setup(kernel) регистрирует: provide / register_tool / on / register_runtime
       │     каждая регистрация = эффект плагина (undo-колбэк)
       ├─ setup может вернуть teardown → последний эффект
       └─ сбой setup → откат всех эффектов
unload_plugin → эффекты в обратном порядке; стек сервиса/инструмента возвращает предыдущую реализацию
reload_plugin → unload + importlib.reload + load (горячая замена)
```

Плагины по умолчанию: `llm_providers`, `runtimes` (native, claude_code), `builtin_tools`, `skill_tools`,
`board_tools`, `evolve_tools`. Свои — через `plugins: [...]` в конфиге, отключение — `disable_plugins: [...]`.

Производительность (замер на 4 ядрах): поиск сервиса — 0.1 мкс; вызов через ядро без перехватчиков — 0.4 мкс,
с одним перехватчиком — 1.7 мкс.

## Изоляция задач и песочница

Не опора, а слой под опорой «Цикл до результата»: включается конфигом (`isolation.worktrees`, `sandbox.mode`),
по умолчанию выключен, контракты опор не меняет (`done` по-прежнему ставит только ревьюер).

```
job_work    Isolation.ensure(task)   commit внешних правок shared/ в main → worktree task/<id> из main
            ctx.deliverables = worktree   shared/…, $ARTEL_SHARED, --add-dir (Claude Code, Codex) → worktree
job_review  Isolation.integrate      commit worktree, merge main → task; конфликт → merge_conflict без ревьюера
            run_gates(cwd=worktree)  проверки на кандидате; reviewer видит worktree и список изменённых файлов
on_review   принято → Isolation.accept: fast-forward main + read-tree -m -u в shared/, worktree удаляется
            конфликт (база ушла во время ревью) → комментарий MERGE CONFLICT, задача ready, маркеры в worktree
            отказ «START OVER» → Isolation.discard (reset к main); cancel/split → drop
bash        sandbox.plan: bwrap --ro-bind / / + --bind (worktree, workspace, temp, writable) | sandbox-exec | заметка
```

Общий `shared/` меняется только через принятое слияние (или вне задач: люди, аудитор); слияние сериализовано
замком, правки никогда не перезаписываются молча. Код: `artel/worktree.py`, `artel/sandbox.py`; тесты:
`tests/test_isolation.py`, `tests/test_sandbox.py`.

## Как развивается Artel

- **Структурные изменения опор** (режим `design` в `roadmap.yaml`) проектируются и реализуются вручную, с
  тестами-инвариантами.
- **Остальные пункты дорожной карты** (режим `evolve`) реализует сам Artel через `artel evolve --roadmap N`:
  следующие N пунктов по волне и зависимостям (`after`) становятся гипотезами; исходники донора клонируются и
  передаются команде только для чтения, с пометкой лицензии; ветка, тесты (включая инварианты), бенчмарк,
  решение о слиянии. Итог записывается в `roadmap.yaml` (`status`, `result`) и `docs/ROADMAP.md` отдельным
  коммитом; правка только дорожной карты не запускает новый базовый замер. Команда не может менять `roadmap.yaml`.
- `artel roadmap status|next|render` — состояние, очередь, генерация `docs/ROADMAP.md`; тест сверяет, что
  сгенерированный файл совпадает с yaml.
- **Пункты карты внедряются, а не соревнуются.** Для них нет отсева и конкурса: все реализованные пункты
  поколения сливаются на одну интеграционную ветку (тесты после каждого слияния) и меряются одним прогоном.
  Критерий — функция работает (её тесты и инварианты проходят) и ничего не сломала: нет подтверждённой повторным
  прогоном регрессии, стоимость не выше +25%. Улучшения бенчмарка не требуется. Если регрессия есть, виновник
  ищется прогоном только упавших задач, и пункт возвращается своей команде с проваленными проверками; так же — при
  падении тестов. После двух неудачных доработок пункт получает статус `blocked` («нужна помощь») и ждёт решения
  человека, а не выбрасывается. Отсев, финалисты и конкурс остаются только для свободных гипотез.
- **Разбор чужих проектов пополняет карту.** `artel absorb [owner/repo]` клонирует проект (без аргумента —
  самый релевантный ещё не изученный живой харнесс из реестра на 1391 проект), агент-аналитик читает код, сверяет
  с картой и опорами и сдаёт находки с файлами-источниками. Находки с fit ≥ 0.6, не дублирующие пункты карты,
  становятся пунктами волны 4 с донором, путями, лицензией, планом и критериями; то, что задевает опору,
  получает режим `design` и в эволюцию не идёт. Изученное пишется в `studied.yaml` и в `docs/ROADMAP.md`.
- **Цикл направленного самоулучшения** — `artel evolve --cycle K`: K раз «изучить следующий проект → реализовать
  следующие пункты карты по порядку». Найденное встаёт в очередь после запланированных волн; `absorb --run`
  реализует его сразу — только явным решением.
- **Свободные гипотезы** эволюционера по диагностике — отдельный режим, не основной.

## Стоимость ролей

- Провайдер Anthropic ставит точки кэша (`cache_control`) на описания инструментов и системный префикс; рантайм
  `claude_code` не передаёт `--append-system-prompt` повторно при возобновлении сессии.
- Контекст ревьюера и аудитора ограничен окном «начало + конец» (`window_text`).
- Роли `librarian`, `refiner`, `auditor` на провайдере Anthropic идут на дешёвой модели (`roles.cheap_model`,
  `roles.cheap_roles`), если в `models` для роли нет явной записи. Итоговый аудит цели пропускается на лёгком
  чистом прогоне (`roles.skip_on_easy`); любая неудача или крупный прогон сохраняют полный аудит.
