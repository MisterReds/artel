# Разбор харнессов, октябрь 2026

Очередь — `artel roadmap study -n 12` (живые харнессы по релевантности, без уже изученных и доноров карты).
Изучены по исходникам (клоны `--depth 1`): ECC, Fusion, DeerFlow, Hive, AgentTeams, oh-my-claudecode,
Munder Difflin. Пропущены: `holny/Agent-Harness-Develop-Book` — это книга, а не код;
`thClaws/thClaws`, `huangruiteng/loopx`, `ruflo`, `everything-claude-code` (старое имя ECC) — перенесены на
следующий раз.

Как отбирали: в карту попадает только то, чего в Artel нет или что сделано хуже, и что может улучшить результат,
надёжность, прозрачность, стоимость или работу с телефона. Каждое утверждение «у Artel хуже» сверено с кодом Artel.
Пункты — волна 4 в `roadmap.yaml`; дополнения к уже запланированным пунктам — строки `note:`; итоги — в `studied.yaml`.

## ECC (`affaan-m/ECC`, MIT)

**Устройство.** В основном это набор плагинов, хуков, скиллов и агентов для Claude Code (десятки ревьюеров под
конкретные языки, установщик хуков). Плюс `ecc2/` — альфа управляющего слоя на Rust: сессии в SQLite, демон,
worktree на сессию, оценка риска, уведомления, проверка «продвигать ли новую конфигурацию харнесса».

**Что лучше, чем в Artel.**
- `ecc2/src/harness_eval.rs` — кандидат продвигается только по парным замерам: минимум прогонов, рост среднего
  и доля выигранных пар — все три условия разом. В Artel `Policy.decide` (`artel/evolve/engine.py`) засчитывает
  свободной гипотезе любой прирост за один прогон, а на 7 задачах это шум. → **A-ecc-paired-promotion** (design:
  меняет решение опоры «измеряемая эволюция»).
- `ecc2/src/session/daemon.rs`, `session/manager.rs` (`enforce_session_heartbeats`) — сессию, давно не подававшую
  признаков жизни, помечают stale или завершают. Artel пишет heartbeat прогонов, но `Board.stale_runs` никто не
  вызывает; у рантаймов Claude Code и Codex есть только общий таймаут 40 минут. → **A-ecc-run-heartbeat-watchdog**.
- `ecc2/src/observability/mod.rs` — детерминированная оценка риска каждого вызова инструмента (тип инструмента,
  секретные файлы, масштаб, необратимость) → note к **W2-guardian**: дешёвый первый проход до модели.
- `ecc2/src/notifications.rs` — включение по событиям и тихие часы → note к **W2-remote-and-notify**.

**Не берём.** Установщик хуков и плагинов для Claude Code (рантаймы у Artel свои); каталог ревьюеров по языкам
(души исполнителей пишет планировщик под проект; готовый каталог только утяжеляет промпт); TUI (у Artel
веб-дашборд, а нужен телефон).

## Fusion (`Runfusion/Fusion`, MIT)

**Устройство.** Канбан-«фабрика» на TypeScript: планировщик пишет `PROMPT.md` (шаги, область файлов, критерии),
каждая задача идёт в своём worktree, гейты plan → review → execute → review, самолечение, уведомления, туннели
для удалённого доступа. Код очень большой (`self-healing.ts` — 17 тыс. строк), много пометок о разборе регрессий.

**Что лучше, чем в Artel.**
- `packages/engine/src/executor/file-scope-lease-dispatch-gate.ts`, `scheduler.ts` (`findFileScopeOverlaps`) —
  задачи с пересекающейся областью файлов не идут одновременно. В Artel исполнители параллельно пишут в один
  `shared/`, а у задачи нет поля «какие файлы». → **A-fusion-file-scope-lease** (дешёвый шаг до W2-worktree-isolation).
- `packages/engine/src/healing/stuck-task-detector.ts` — петля распознаётся по окну из 40 отпечатков вызовов,
  у которых мала доля уникальных; правило «одна команда занимает половину окна» сознательно не используется.
  `LoopDetector` в `artel/agent.py` ловит только одинаковые вызовы подряд, а чередование A, B, A, B пропускает.
  → **A-fusion-novelty-loop-window**.
- `packages/engine/src/execution-block-classifier.ts` — точные коды сети (ECONNRESET, ETIMEDOUT, EAI_AGAIN) и
  хоста (ENOSPC, EROFS, ENOMEM). В Artel `failures.classify` знает только limit / setup / work, поэтому сетевой сбой
  тратит попытки, а переполненный диск повторяется впустую. → **A-fusion-external-obstacle-classes**.
- `packages/engine/src/executor/create-review-dispute-tool.ts` — исполнитель может оспорить замечание ревью;
  спор остаётся открытым, пока ревьюер не вынесет решение. Сейчас ошибочный отказ в Artel сжигает попытки до
  срабатывания предохранителя. → **A-fusion-review-dispute**.
- `notification/ntfy-provider.ts` (ntfy с переходом прямо к задаче), `remote-access/` (tailscale funnel /
  cloudflared) → note к **W2-remote-and-notify**.

**Не берём.** Связку нескольких машин и PostgreSQL (Artel — одна машина и SQLite); «компании» из 440 агентов
(нет данных, что это улучшает результат); нативное приложение на Capacitor (PWA с уведомлениями даёт то же
дешевле); уровни надзора планировщика (пересекается с W3-plan-review).

## DeerFlow (`bytedance/deer-flow`, MIT)

**Устройство.** Супер-агент на LangGraph: ведущий агент, субагенты, песочницы, скиллы, несколько бэкендов памяти,
IM-каналы, цель сессии с оценкой после каждого прогона, `make doctor` и обезличенные пакеты для отчёта об ошибке.

**Что лучше, чем в Artel.**
- `backend/packages/harness/deerflow/subagents/acceptance_checks.py` — часть критериев приёмки проверяется кодом:
  `file:<path> exists|non-empty|json-valid` и `tests_passed:<cmd>`. Последний засчитывается, только если в журнале
  есть именно этот вызов bash, а в конце его вывода — итог прохождения; «0 passed» и найденные падения проверку
  проваливают. Ответ трёхзначный: выполнено / не выполнено / не проверено, а «не проверено» никогда не
  засчитывается молча. В Artel любой критерий судит модель-ревьюер по доказательствам в свободной форме.
  → **A-deerflow-typed-criteria**: дешевле (явный провал отклоняется без вызова модели) и надёжнее.

**Не берём.** Рантайм LangGraph, IM-каналы, RAGFlow, управление браузером — это другой продукт (чат-ассистент).
DeerMem — память о пользователе чата; память исполнителей уже покрывает W3-two-phase-memory. Режим snapshot для
субагентов — у Artel пока нет субагентов внутри прогона.

## Hive (`aden-hive/hive`, Apache-2.0)

**Устройство.** «Колония» на Python: ведущий агент (Queen) сначала сам делает одну единицу работы, превращает её
в скилл и инструкцию, затем клонирует себя в исполнителей; общий журнал-трекер; парковка и возобновление после
падения; Sentinel — эскалации человеку вне интерфейса.

**Что лучше, чем в Artel.**
- `core/framework/sentinel/` (`manager.py`, `token.py`, `listeners.py`, `store.py`) — эскалация уходит в
  Telegram или Slack с меткой `ref:`. Метка — HMAC от идентификатора эскалации на секрете установки (файл с
  правами 0600). Ответ принимается длинным опросом getUpdates: соединение только исходящее, работает за NAT без
  открытого порта. Ответ возвращается в ту задачу, к которой относится; открытые эскалации лежат на диске и
  переживают перезапуск. В Artel (W2-remote-and-notify) уведомления только исходящие. → **A-hive-chat-reply**
  (design) — ответить на задачу прямо с телефона.
- `core/framework/sentinel/classifier.py` — перед эскалацией дешёвая модель отличает настоящий блокер от вопроса
  «продолжать?»; жёсткие блокеры (вход, падение) эскалируются без проверки. В Artel `task_block(needs_human=true)`
  сразу уходит человеку. → **A-hive-escalation-filter**: меньше лишних остановок «ждёт человека».

**Не берём.** «Сначала пилот, потом раздача» — идея записана, но нет данных, что она поможет DAG-планировщику Artel
на бенчмарке. Браузерное расширение и MCP-инструменты для бизнес-систем — вне задач Artel. Подталкивание при
зависании потока до первого токена касается только нативного рантайма и вошло в A-ecc-run-heartbeat-watchdog.

## AgentTeams (`agentscope-ai/AgentTeams`, Apache-2.0)

**Устройство.** Платформа на Kubernetes: менеджер и исполнители в отдельных контейнерах, комнаты Matrix, где
человек видит всё; общие файлы в MinIO; шлюз Higress хранит настоящие ключи; TeamHarness — задачи с таблицей
переходов, историей и уведомлениями о завершении.

**Что лучше, чем в Artel.**
- `README.md`, `docs/usage/higress-gateway-api.md`, `shared/lib/agentteams-env.sh` — исполнители не видят настоящих
  ключей: у них только ограниченные ключи шлюза. В Artel инструмент `bash` нативного рантайма получает весь
  `os.environ` (`artel/plugins/builtin_tools.py`), включая ключи провайдеров. → **A-agentteams-secret-free-env**.
- `docs/design/teamharness/task-transition-engine.md`, `plugins/teamharness/contracts/task-transitions.json` —
  таблица переходов в JSON, единая точка входа, история переходов с автором, ошибка при переходе не по порядку
  подсказывает правильное действие → note к **W3-state-machine**.

**Не берём.** Matrix, MinIO, Higress, CRD Kubernetes — тяжёлая инфраструктура, а Artel работает на одной машине.
Несколько рантаймов в одной комнате — это направление W3-acp-runtime.

## oh-my-claudecode (`Yeachan-Heo/oh-my-claudecode`, MIT)

**Устройство.** Плагин и CLI для Claude Code: командный конвейер plan → prd → exec → verify → fix, исполнители в
tmux для разных CLI, deep-interview с оценкой неясности, уровни проверки, уведомления с приёмом ответов,
предполётная проверка опасных действий (lookout).

**Что лучше, чем в Artel.**
- `skills/deep-interview/SKILL.md` — неясность считается по формуле `1 - (0.4·цель + 0.3·ограничения +
  0.3·критерии)`; пока она выше порога, исполнение не начинается, а вопрос бьёт в самое слабое измерение. Artel
  планирует любую цель сразу, а короткая цель, набранная с телефона, приводит к работе команды наугад.
  → **A-omc-clarify-gate**.
- `src/verification/tier-selector.ts` — объём проверки зависит от размера изменения (файлы, строки, безопасность).
  У Artel ревьюер всегда на одной модели, хотя теневой git-снимок уже знает размер изменения.
  → **A-omc-review-tiers** (стоимость).
- `src/notifications/redact.ts` — маскирование токенов (Anthropic, GitHub, Slack, Telegram, AWS, Bearer). В Artel
  нигде нет маскирования: напечатанный ключ попадает в `events.jsonl`, ленту дашборда и контекст ревьюера.
  → **A-omc-secret-redaction**.

**Не берём.** Исполнители в tmux для разных поставщиков (общий путь — W3-acp-runtime); HUD, wiki и десятки скиллов
(удобства Claude Code, а не поведение харнесса); lookout (пересекается с W2-execpolicy и W2-guardian);
reply-listener (та же идея, что A-hive-chat-reply, но маршрутизация по меткам у Hive чище).

## Munder Difflin (`chaitanyagiri/munder-difflin`, MIT)

**Устройство.** Настольное приложение на Electron: оборачивает терминальные CLI (Claude Code, Codex, Gemini и
другие) в «офис» агентов. Обмен — через git-репозиторий «улья» с почтовыми ящиками и одним коммитером, память в
markdown, предохранитель от разгона, аватары на 2D-этаже.

**Что лучше, чем в Artel.**
- `src/main/breaker.ts` (`workTokensOf`), `src/main/usage.ts` — бюджет считается по «рабочим» токенам без чтения
  кэша: Munder обнаружил, что чтение кэша давало ~99% учтённого числа. В Artel рантайм Claude Code прибавляет
  `cache_read_input_tokens` к `input_tokens` (`artel/runtimes/claude_code.py`), и на этом же числе работает
  `budgets.max_total_tokens`. → **A-munder-work-tokens**.
- `src/main/breaker.ts` — лестница «подсказать → ограничить → остановить» по скорости расхода токенов, шквалу
  ошибок и отсутствию изменений в рабочей папке → note к **W3-tree-budget**.
- `src/main/hive.ts` — один маршрутизатор доставляет письма из outbox во inbox, сами агенты в git не пишут →
  note к **W3-mailbox**.

**Не берём.** Аватары, диктовку и расшифровку встреч (на результат не влияет); протокол «конец рабочего дня»
(Artel и так сохраняет рабочие папки и возобновляет прогоны); арбитраж GOD-агента (эту роль уже играет replan
менеджера).

## Итог

Добавлено 14 пунктов волны 4 (12 evolve, 2 design) и 5 заметок к существующим пунктам. Самые ценные по
соотношению цены и пользы: A-munder-work-tokens (бюджет сейчас считается неверно), A-agentteams-secret-free-env и
A-omc-secret-redaction (ключи сейчас открыты исполнителям и журналу), A-fusion-novelty-loop-window,
A-ecc-run-heartbeat-watchdog. Для работы с телефона — A-hive-chat-reply и A-omc-clarify-gate.
