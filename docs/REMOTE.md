# Доступ с телефона: удалённый дашборд и PWA

По умолчанию `artel web` слушает только `127.0.0.1` и пускает без входа: он доступен лишь на этой машине.
Удалённый режим открывает дашборд для телефона, но только после входа по токену.

> **Внимание: удалённый режим без TLS передаёт токен и cookie сессии по сети открытым текстом.**
> Любой в той же сети (Wi‑Fi кафе, провайдер, прокси) может их перехватить и получить полный доступ к Artel —
> а Artel запускает агентов, которые выполняют команды на вашей машине. Открывайте дашборд снаружи только по HTTPS:
> один из рецептов ниже. Если запрос пришёл не по HTTPS и не с localhost, дашборд показывает предупреждение.

## Как устроен вход

- `artel web --remote` (или `web: {remote: true}` в `~/.artel/artel.yaml`) при первом запуске выпускает токен
  доступа (`secrets.token_urlsafe`) и печатает его в терминале **один раз**. На диске лежит только соль и хэш
  scrypt в `~/.artel/web_auth.json` (права `600`); сам токен нигде не сохраняется и не пишется в логи.
- `artel web token --new` выпускает новый токен и закрывает все сессии (в том числе у работающего сервера).
- На странице входа токен вводится один раз; сервер выдаёт cookie `artel_session` — случайный id, `HttpOnly`,
  `SameSite=Strict`, `Secure` за HTTPS-прокси. Сессии хранятся на сервере (только SHA-256 от id), живут
  `web.session_days` дней (по умолчанию 30), кнопка «Выйти» закрывает сессию на этом устройстве.
- Без сессии каждый `/api/*` и поток событий (SSE) отвечает `401`, страницы перенаправляют на `/login`.
  Открыты только страница входа, статика (шрифты, иконки), манифест и service worker.
- Пять неверных попыток с одного адреса за 10 минут — дальше `429` до конца окна. За обратным прокси на этой же
  машине адрес клиента берётся из `X-Forwarded-For`; от не-локальных клиентов этот заголовок игнорируется.

Настройки (`~/.artel/artel.yaml`):

```yaml
web:
  remote: true        # то же, что artel web --remote
  host: 127.0.0.1     # за прокси на этой машине; 0.0.0.0 — слушать все интерфейсы
  session_days: 30
```

## Рецепт 1: Caddy и свой домен (автоматический TLS)

Нужны домен с A/AAAA-записью на эту машину и открытые порты 80/443. Caddy сам получит и продлит сертификат
Let's Encrypt.

```sh
artel web --remote --host 127.0.0.1 --port 8765    # снаружи Artel не виден, только через Caddy
```

`/etc/caddy/Caddyfile`:

```
artel.example.com {
    reverse_proxy 127.0.0.1:8765
}
```

```sh
sudo systemctl reload caddy
```

Caddy передаёт `X-Forwarded-For` и `X-Forwarded-Proto: https`, поток событий (SSE) проксируется без буферизации.
Откройте `https://artel.example.com` на телефоне и введите токен.

## Рецепт 2: Tailscale — приватно и без домена

Дашборд виден только вашим устройствам в tailnet, с настоящим HTTPS-сертификатом `*.ts.net`.

1. Установите Tailscale на машину с Artel и на телефон, войдите в один аккаунт.
2. В админке Tailscale включите MagicDNS и HTTPS Certificates (DNS → HTTPS Certificates).
3. Запустите:

```sh
artel web --remote --host 127.0.0.1 --port 8765
tailscale serve --bg 8765          # https://<машина>.<tailnet>.ts.net → http://127.0.0.1:8765
tailscale serve status              # покажет адрес
```

Откройте показанный адрес на телефоне. Снять публикацию: `tailscale serve --https=443 off`.
Не используйте `tailscale funnel` — он открывает дашборд всему интернету.

## Установка на телефон (PWA)

Открыв дашборд по HTTPS: Safari → «Поделиться» → «На экран Домой»; Chrome/Android → меню → «Установить приложение».
Приложение открывается без адресной строки, в цветах Artel. Service worker кэширует только оболочку (страницу,
шрифты, иконки); данные (`/api/*`, поток событий) всегда идут с сервера и никогда не кэшируются.
